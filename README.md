# signion-backoffice

SIGNION BackOffice 관리자 화면 프로토타입 (v0.2)

- `index.html` — 단일 파일 프로토타입 (서버 불필요, 브라우저로 바로 열림)
- `assets/` — SIGNION 로고 원본 SVG (BI 가이드라인 기준)

메뉴 구성은 `backOffice관리자_메뉴구성도.xlsx` 기준이며, 화면의 고객·거래 데이터는 모두 프로토타입용 가상 데이터입니다.
로그인 화면에서는 아무 값이나 입력하면 진입합니다.

## 모든 목록 공통 — 다중검색 · X

- 모든 목록 화면(50개, 상세에 「검색」이 있는 화면)에 종합관리와 같은 기준 적용. 목록 위 예전 「다중검색」 패널 버튼은 없앰.
- 배치는 종합관리와 동일: 탭 아래 제목 줄에 `[다중] [다중검색 N] | [수정] [삭제] …` 한 줄(화면에 그 줄이 없으면 만들고, 하단 버튼이 2개 이하면 같은 줄로 옮김), X는 첫 항목 줄(전산코드 · 일시 등) 값 옆.
- 「다중」을 켜면 상세 항목 옆 「검색」이 「선택」 체크로 바뀌고 그 칸이 검색 조건 입력이 됨 (선택지가 있는 항목은 드롭다운, 그 밖은 글자 입력 · 포함 검색). 실제 데이터는 바뀌지 않음.
- 검색 항목을 **2개 이상** 선택 → 「다중검색」 → 모두 만족하는 항목만 목록에 표시. 목록 머리에 조건 칩(× · 조건 모두 해제). 0건이면 적용하지 않고 안내.
- X: 모든 칸 비우기 ↔ 한 번 더 누르면 원래 값 복원. 「다중」을 끄면 조건 해제.
- 자동 상세 화면(로그 · 기초코드 · 과금 · 공통 서버 등)은 항목마다 「검색」 버튼을 추가(금액 · 숫자 열 제외). 별도 상세가 있는 대리점 화면은 상세 아래 「검색 항목」 칸으로 제공. 메시지코드관리 상세에는 프로그램서비스 · 사용언어 · 메세지코드 · 타이틀 · 상태 「검색」 추가.

## 모든 목록 공통 — 전체 선택 · 엑셀

- 목록 머리의 전체 선택 체크 = **현재 검색 조건(다중 검색 포함)에 맞는 모든 항목**을 선택 (다른 페이지 포함). 다시 누르면 해제되고 현재 행만 체크로 남음.
- 엑셀 버튼: 2건 이상 체크하면 「선택 N건 엑셀」로 바뀌고 **선택한 항목만** 내려받음. 체크가 1건 이하이면 검색 결과 전체를 내려받음. 다운로드는 감사LOG에 기록.

## 인증거래처관리 › 종합관리 (레거시 LORDMAN 화면 기준 재구성)

| 영역 | 내용 |
| --- | --- |
| 목록 · 상세 한 화면 | 들어오면 첫 행이 자동 선택되고 오른쪽에 상세가 열림. 상세 칸은 제목 줄부터 화면 아래까지 길게 (제목 · 검색 도구 줄은 목록 폭만 차지, 모든 목록 | 상세 메뉴 공통). 목록은 화면 높이에 맞춰 페이지(↑↓ 이동), 가로는 목록 안에서만 스크롤 |
| Split View | 목록 | 상세 경계선을 끌어 상세를 넓히거나 좁힘 (목록은 최소 440px 유지). 경계선 가운데 「‹」 버튼 = 상세 크게 보기(다시 누르면 원래 크기), 경계선 두 번 누르기 = 기본 폭, 경계선에 초점 두고 ←→ 키로도 조절. 폭은 모든 메뉴 공통으로 기억 |
| 상세 탭 | 기본정보 · 사업자정보 · 거래정보 · 등록서류관리 · 기타정보 · 자료관리. 기본정보의 전산코드 오른쪽에 「메모등록」(레거시 위치) — 등록한 메모는 자료관리 탭과 작업관리 › 자료메모관리에 바로 보임. 등록 창과 같은 칸 구성. 거래정보 › 사용서비스 · 사용옵션은 「사용」 체크박스만 색으로 구분(체크 = 파란 체크박스 · 파란 굵은 「사용」, 미체크 = 회색 빈 칸, 보기 모드에서도 동일). 목록 헤더 체크(전체 선택)를 다시 누르면 해제되고, 현재 선택된 행만 체크로 남음(모든 목록|상세 화면 공통) |
| 탭별 버튼 | 탭마다 「(탭) 등록」 · 「수정」 · 「중지」. 수정은 탭 전체를 한 번에 고치고 저장 · 취소 (저장 안 한 변경이 있으면 이동 전에 확인) |
| 제휴사 접속정보 관리 | 제목 옆 버튼 → 모달 창으로 열림 (제목 줄 · 검색/등록/수정/삭제/삭제자료 표시/엑셀 도구 줄 · 왼쪽 상세 · 오른쪽 접속 목록). 닫기: ✕ · Esc · 창 바깥 누르기 (편집 중이면 먼저 확인). 삭제 등 확인창은 모달 위에 떠서 입력 중인 내용이 지워지지 않음. 인증정보 탭은 접속 masterToken · MasterKey · IvKey 전체 값 (읽기 전용 · 복사 · 감사LOG) |
| 다중 검색 | 상단 「다중검색」 버튼은 없앰. 상세 탭 줄을 레거시처럼 한 줄로: [다중] [다중검색] | [등록] [수정] [중지] (「다중검색」은 항상 표시 — 다중이 꺼져 있으면 눌렀을 때 다중을 켬, 좁은 화면에서는 등록 · 수정 · 중지 아이콘 생략). 켜면 항목 옆 「검색」이 「선택」 체크로 바뀌고 그 칸이 검색 조건 입력으로 열림(수정 아님 — 거래처 데이터는 안 바뀜). 원하는 옵션을 고르거나 글자를 입력하면 자동 체크, 그대로 둔 칸은 체크하면 현재 값 사용 → 검색 항목을 **2개 이상** 선택한 뒤 「다중 검색 N」(또는 입력 칸에서 Enter)을 누르면(1개 이하이면 버튼 비활성 · 안내)(결과 0건이면 적용하지 않고 안내) · 전산코드 줄 「메모등록」 앞의 X(레거시 위치 · 항상 표시, 수정 중에는 비활성 · 한 번 더 누르면 원래 값 복원 — 누른 상태는 보라색으로 채워짐)는 다중을 켜고 칸에 있던 거래처 값까지 모두 빈칸으로 비우고(전산코드만 남김, 실제 데이터는 그대로) 체크 · 적용된 검색도 해제 → 찾을 값만 새로 입력 · 선택 · 선택값은 같은 값, 글자 입력은 포함 검색으로 체크한 값을 모두 만족하는 거래처만 보임. 목록 머리에 조건 칩(× · 조건 모두 해제). 「다중」을 끄면 조건 해제 · 한 항목씩 검색 |
| 확인 팝업 | 모든 예/아니요 확인창을 「계약서비스중지」 창과 같은 모양으로 통일 — 아이콘 · 질문 · 설명, [아니요(N)] [예(Y)], Y/N · Enter/Esc |
| 예시 데이터 | 상세의 모든 칸이 채워져 보이도록 거래처 10곳에 가상 데이터 (실데이터 연결 시 `예시 데이터` 블록만 삭제) |

- 새 거래처 등록은 상세 기본정보 탭의 「거래처 등록」 버튼으로 합니다.
- 하위 메뉴(접속정보관리 · 요금관리 · 사업자정보관리 · 업체대표자관리)도 같은 틀입니다: 회사당 1행 목록 | 오른쪽 상세, 첫 행 자동 선택, 페이지 스크롤 없음, 차트 없음.
  - 접속정보관리: 목록에 Web 접속 URL(개수 + 첫 URL) · iOS · AOS · 서버 IP, 오른쪽에서 접속정보 등록 · 수정 · 삭제와 인증정보
  - 요금관리: 오른쪽에 거래정보(사용서비스 · 거래수수료) / 사업자정보관리: 사업자정보 / 업체대표자관리: 대표자정보 (목록의 개인정보는 가림)
  - 원본 행(접속정보 · 요금 · 사업자 · 대표자)은 코드의 `PDATA`에, 메뉴 목록은 거래처(`PARTNERS`) 기준입니다.
- 사이드바 아래에는 「메뉴 접기」만 두고, 요청사항 · 디자인 가이드 · 저작권 문구는 오른쪽 위 사용자 메뉴로 옮겼습니다.

## 인증내역관리 (레거시 화면 기준)

- 목록(최근 순 · 첫 건 자동 선택) | 오른쪽 상세(기본정보 · 인증서비스 · 인증사진 · 자료관리). 페이지 스크롤 없음, 차트 없음.
- 목록 열: 순번 · 등록일자 · 제휴사ID · 제휴사명 · 승인번호 · 인증완료(완료/중단/진행중) · 결과전달 · 인증상태메시지 · 국가코드 · 여권번호 · 여권성명 · 수수료. 위에 수수료(KRW · USD) 합계.
- 행을 두 번 누르거나 상세의 「인증 상세 내역 보기」 → 「인증 상세 내역」 팝업: 오른쪽 단계별 내역(순번 · 인증코드 · 인증단계명 · 진행결과 · 처리일시), 위에 그 건의 수수료 · 엑셀. 팝업 안에서 단계를 누르거나 ↑↓ 키로 이동, Esc · 닫기로 닫음 (목록 높이는 그대로). 단계를 누르면 왼쪽에 인증단계 · 상태코드 · 상태메시지 · 시스템코드 · 시스템메시지 · 시작시각. 중단 건은 실패 단계가 먼저 선택됨.
- 기본 기능: 검색 · 다중검색 · 인증삭제(논리삭제, 삭제자료 표시로 조회) · 메모등록 · 엑셀. 상세 항목 옆 「검색」은 그 값으로 목록을 걸러 줌.

## 발행토큰관리 (레거시 화면 기준)

- 접속정보(접속종류 · 접속정보 · 데이터응답URL · 서버접속IP)마다 발행된 인증 Token 1행. 새 접속정보가 등록되면 Token이 자동 발행되고, 접속정보를 삭제하면 삭제코드 1=삭제.
- 목록(IDX · 등록일 · 제휴사ID · 제휴사명 · 접속종류 · 접속정보 · 데이터응답URL · 서버접속IP · Token종류 · tokenKey · 생성시간 · 삭제코드) | 오른쪽 상세(발행 정보 · 접속 정보 · Token — tokenKey 전체, 읽기 전용, 복사 시 감사LOG).
- 기본 기능은 검색(· 다중검색 · 삭제자료 표시 · 엑셀). 거래처별 masterToken 은 「제휴사 접속정보 관리 › 인증정보」에서 관리하며 코드상 `PDATA.token`.
- 화면 틀은 공통(`mdPage` · `MDP[route]`)이라 같은 형태의 메뉴는 열 · 상세만 정의하면 됩니다.

## 암호화KEY관리 (레거시 화면 기준)

- 목록(IDX · 등록일 · 제휴사ID · 제휴사명 · 용도 · 암호화방식 · MasterKey · IvKey · 삭제코드) | 오른쪽 상세(발행 정보 · 암호화 KEY — MasterKey · IvKey 전체 32자리 HEX, 읽기 전용, 복사 시 감사LOG). 기본 기능은 검색.
- 「제휴사 접속정보 관리 › 인증정보」와 같은 KEY 자료를 씁니다. 거기서 「암호화 KEY 생성」으로 재발급하면 이전 KEY는 삭제코드 1=삭제(재발급)로 목록에 남습니다.

## 메시지코드관리 (레거시 화면 + 기능 추가 요청)

- 목록(IDX · 등록일 · 프로그램서비스 · 메세지코드 · 사용언어 · 메세지 타이틀 · 메세지 내용 · 시스템 메시지 · 상태) | 오른쪽 상세(수정 · 삭제).
- 개별 등록: 「등록」 → 프로그램서비스 · 사용언어 · 메세지코드 · 메세지 타이틀 · 메세지 내용 · 시스템 메시지 → 「메세지코드정보저장」. 같은 프로그램 · 언어 · 코드 중복은 막음.
- 일괄 등록: 「메세지코드업로드」 → 엑셀(.xlsx · .csv) 선택 → 미리보기(등록 가능 · 새 코드 · 내용 바뀜 · 오류 줄) → 「자료등록」. 같은 코드는 내용을 갱신, 오류 줄은 제외. 양식 내려받기 제공. (.xlsx 읽기는 SheetJS를 CDN에서 불러옴 — 안 되면 CSV로 안내)
- 초기화: 「메세지코드초기화」 → 확인창 → 「예」 시 전체 삭제(감사LOG · 데이터수정LOG), 「아니요」 시 그대로. SysAdmin · 연구소 개발자만 보임.

## LOG관리 › 인증요청 LOG (레거시 「인증요청로그」, 이전 이름 API 요청 LOG)

- 목록(IDX · 등록일 · 제휴사ID · 제휴사명 · cmd · API 커맨드 · 승인번호 · 요청일시, 최근 순) | 오른쪽 상세(레거시처럼 한 칸: 전산코드 · 등록날짜 · 제휴사명 · API커맨드 · (승인번호) · API LOG 요청 원문 JSON(읽기 전용 · 복사, 줄바꿈 표시) · 맨 아래 요청일시). 기본 기능은 검색.
- 원문의 비밀번호 · 토큰은 가려서 저장(••••). 다른 LOG 메뉴도 같은 목록 | 상세 화면(아래 「나머지 메뉴」 참고).

## LOG관리 › 어뷰징 LOG (`#/log/abuse`)

- 여권 · 안면 인증 어뷰징 시도(타인 여권 · 얼굴 불일치 · 여권 위·변조 · 반복 시도)를 AI 서버가 탐지 · 차단한 기록. **읽기 전용** — 등록 · 수정 · 삭제 없음. 내부 백오피스와 KT 통합 어드민이 같은 화면 · 같은 AI 서버 기록을 봅니다.
- 위: 요약 카드 4개(어뷰징 시도 · 차단/탐지 · 영향 제휴사 · 최다 에러코드) — 기간 · 필터를 바꾸면 같이 바뀜.

## 작업관리 › 직원관리 (레거시 「직원관리」)

- 목록(전산코드 · 등록날짜 · 성명 · 아이디 · 핸드폰번호 · 직급 · 부서 · 소속회사 · 상태 · 국가명) | 오른쪽 상세 탭: 기본정보(연락처 · 수신 동의 · 주소 · 아이디 · 카드(가림) · 계좌) / 세부정보(소속회사 · 부서 · 직급 · 권한 역할 · 등록서류) / 거래정보(구매 한도 · 수수료율 · 거래 제한 7종 · 사유) / 기타정보(비고 · 상태 · 변동날짜 · 변동사유 · 자료등록자) / 자료관리(메모등록 LIST) / 서비스 권한.
- 서비스 권한: 레거시와 같은 배치 — 왼쪽 「서비스 기능 LIST」 · 오른쪽 「서비스 권한 선택 LIST」. 행을 **체크하면 바로 반대쪽 표로** 옮겨지고, 반대쪽 표로 **끌어다 놓아도** 옮겨짐(행 두 번 누르기도 됨). 머리글 체크는 지금 보이는 행 모두(20개 넘으면 확인). 검색 · 메인메뉴 필터, 「역할 기본값」으로 되돌리기. 바꿀 때마다 감사LOG.
- 직원별 권한 실제 적용: 목록을 한 번이라도 바꾼 직원은 「직원별 권한 적용 중」 — 그 직원이 로그인하면 이 목록에 있는 메뉴 · 버튼만 보이고 쓸 수 있음(역할 권한 대신). 안 바꾼 직원은 「역할 권한 적용 중」으로 권한관리의 역할 권한을 그대로 씀. 「이 직원으로 미리보기」로 그 직원 화면을 확인(위 막대의 「미리보기 끝내기」로 돌아옴). 정지된 직원은 어떤 메뉴도 못 씀. 잠김 방지: 본인 계정의 직원관리 · 권한관리 조회 · 수정 권한은 뺄 수 없음.
- 도구: 등록 · 수정 · 정지(사유 필수, 정지된 직원은 「정지해제」) · 신분증(이미지)등록(타이틀 + 이미지, 세부정보 › 등록서류에 추가) · 상세의 메모등록. 본인 계정은 정지할 수 없음. 등록서류 보기는 개인정보 열람으로 감사LOG.
- 직원등록 · 직원수정 창(기본정보 · 세부정보 · 거래정보 · 기타정보 탭): 아이디중복검사를 해야 저장, 비밀번호는 영문 + 숫자 8자 이상, 카드 · 계좌 「자동발급」은 가상카드 · 가상계좌 채번관리의 대기 번호를 넣고 저장할 때 발급 처리. 카드 · 계좌 비밀번호 숫자 4자리, 율(%)은 0~100, 할부 36개월까지, 거래 제한을 걸면 사유 필수. 오류가 있는 탭에는 빨간 점이 붙고 첫 오류 탭으로 이동. 수정은 아이디 고정, 바뀐 항목은 데이터수정LOG · 변동사유에 기록.
- 직원의 권한 역할은 권한관리의 역할 인원 수와 연동.

## 나머지 메뉴 — 같은 화면 흐름으로 통일

- KT통신가입관리(4) · 인증수수료관리 · 대리점 과금관리(5) · 공통 서버 집계(7) · PKD관리 · LOG관리(인증요청 LOG 외 8) · 고객센터(챗봇) · 작업관리(자료메모 · 데이터수정LOG · 감사LOG).
- 모두 목록 | 오른쪽 상세(제목 줄부터 아래까지), 첫 행 자동 선택, 목록은 화면 높이만큼 페이지(↑↓ 이동), 페이지 스크롤 · 차트 · KPI 없음, Split View 적용. 오른쪽에서 열리던 상세 서랍은 없앰.
- 열 · 상세 내용 · 기능 버튼은 각 메뉴의 기존 정의 그대로. 도구 줄: 검색 · 다중검색 · 등록 · 수정 · 삭제 · (메뉴별 기능 버튼) · 리포트 · 삭제자료 표시 · 엑셀. 권한이 없는 버튼은 보이지 않음.
- 등록하면 새 자료가 바로 선택되고, 상세 탭은 다른 행으로 옮겨도 같은 탭이 유지됨.
- 프로그램관리 · 권한관리 · 대시보드는 전용 화면이라 그대로.
