# signion-backoffice

SIGNION BackOffice 관리자 화면 프로토타입 (v0.2)

- `index.html` — 단일 파일 프로토타입 (서버 불필요, 브라우저로 바로 열림)
- `assets/` — SIGNION 로고 원본 SVG (BI 가이드라인 기준)

메뉴 구성은 `backOffice관리자_메뉴구성도.xlsx` 기준이며, 화면의 고객·거래 데이터는 모두 프로토타입용 가상 데이터입니다.
로그인 화면에서는 아무 값이나 입력하면 진입합니다.

## 인증거래처관리 › 종합관리 (레거시 LORDMAN 화면 기준 재구성)

| 영역 | 내용 |
| --- | --- |
| 목록 · 상세 한 화면 | 들어오면 첫 행이 자동 선택되고 오른쪽에 상세가 열림. 목록은 화면 높이에 맞춰 페이지(↑↓ 이동), 가로는 목록 안에서만 스크롤 |
| 상세 탭 | 기본정보 · 사업자정보 · 거래정보 · 등록서류관리 · 기타정보 · 자료관리. 등록 창과 같은 칸 구성 |
| 탭별 버튼 | 탭마다 「(탭) 등록」 · 「수정」 · 「중지」. 수정은 탭 전체를 한 번에 고치고 저장 · 취소 (저장 안 한 변경이 있으면 이동 전에 확인) |
| 제휴사 접속정보 관리 | 제목 옆 체크 → 오른쪽에 전용 칸이 붙음 (제목 줄 · 검색/등록/수정/삭제/삭제자료 표시/엑셀 도구 줄 · 왼쪽 상세 · 오른쪽 접속 목록). 인증정보 탭은 접속 masterToken · MasterKey · IvKey 전체 값 (읽기 전용 · 복사 · 감사LOG) |
| 확인 팝업 | 모든 예/아니요 확인창을 「계약서비스중지」 창과 같은 모양으로 통일 — 아이콘 · 질문 · 설명, [아니요(N)] [예(Y)], Y/N · Enter/Esc |
| 예시 데이터 | 상세의 모든 칸이 채워져 보이도록 거래처 10곳에 가상 데이터 (실데이터 연결 시 `예시 데이터` 블록만 삭제) |

- 새 거래처 등록은 상세 기본정보 탭의 「거래처 등록」 버튼으로 합니다.
- 하위 메뉴(접속정보관리 · 요금관리 · 사업자정보관리 · 업체대표자관리)도 같은 틀입니다: 회사당 1행 목록 | 오른쪽 상세, 첫 행 자동 선택, 페이지 스크롤 없음, 차트 없음.
  - 접속정보관리: 목록에 Web 접속 URL(개수 + 첫 URL) · iOS · AOS · 서버 IP, 오른쪽에서 접속정보 등록 · 수정 · 삭제와 인증정보
  - 요금관리: 오른쪽에 거래정보(사용서비스 · 거래수수료) / 사업자정보관리: 사업자정보 / 업체대표자관리: 대표자정보 (목록의 개인정보는 가림)
  - 원본 행(접속정보 · 요금 · 사업자 · 대표자)은 코드의 `PDATA`에, 메뉴 목록은 거래처(`PARTNERS`) 기준입니다.
- 사이드바 아래에는 「메뉴 접기」만 두고, 요청사항 · 디자인 가이드 · 저작권 문구는 오른쪽 위 사용자 메뉴로 옮겼습니다.

## 인증내역관리 (레거시 화면 기준)

- 목록(최근 순 · 첫 건 자동 선택) | 오른쪽 상세(기본정보 · 인증서비스 · 인증사진 · 자료관리). 페이지 스크롤 없음, 차트 없음.
- 목록 열: 순번 · 등록일자 · 제휴사ID · 제휴사명 · 승인번호 · 인증완료(완료/중단/진행중) · 결과전달 · 인증상태메시지 · 국가코드 · 여권번호 · 여권성명 · 수수료. 위에 수수료(KRW · USD) 합계.
- 행을 두 번 누르거나 상세의 「인증 상세 내역 보기」 → 목록 아래에 단계별 내역(순번 · 인증코드 · 인증단계명 · 진행결과 · 처리일시). 단계를 누르면 왼쪽에 인증단계 · 상태코드 · 상태메시지 · 시스템코드 · 시스템메시지 · 시작시각. 중단 건은 실패 단계가 먼저 선택됨.
- 기본 기능: 검색 · 다중검색 · 인증삭제(논리삭제, 삭제자료 표시로 조회) · 메모등록 · 엑셀. 상세 항목 옆 「검색」은 그 값으로 목록을 걸러 줌.

## 발행토큰관리 (레거시 화면 기준)

- 접속정보(접속종류 · 접속정보 · 데이터응답URL · 서버접속IP)마다 발행된 인증 Token 1행. 새 접속정보가 등록되면 Token이 자동 발행되고, 접속정보를 삭제하면 삭제코드 1=삭제.
- 목록(IDX · 등록일 · 제휴사ID · 제휴사명 · 접속종류 · 접속정보 · 데이터응답URL · 서버접속IP · Token종류 · tokenKey · 생성시간 · 삭제코드) | 오른쪽 상세(발행 정보 · 접속 정보 · Token — tokenKey 전체, 읽기 전용, 복사 시 감사LOG).
- 기본 기능은 검색(· 다중검색 · 삭제자료 표시 · 엑셀). 거래처별 masterToken 은 「제휴사 접속정보 관리 › 인증정보」에서 관리하며 코드상 `PDATA.token`.
- 화면 틀은 공통(`mdPage` · `MDP[route]`)이라 같은 형태의 메뉴는 열 · 상세만 정의하면 됩니다.

## 암호화KEY관리 (레거시 화면 기준)

- 목록(IDX · 등록일 · 제휴사ID · 제휴사명 · 용도 · 암호화방식 · MasterKey · IvKey · 삭제코드) | 오른쪽 상세(발행 정보 · 암호화 KEY — MasterKey · IvKey 전체 32자리 HEX, 읽기 전용, 복사 시 감사LOG). 기본 기능은 검색.
- 「제휴사 접속정보 관리 › 인증정보」와 같은 KEY 자료를 씁니다. 거기서 「암호화 KEY 생성」으로 재발급하면 이전 KEY는 삭제코드 1=삭제(재발급)로 목록에 남습니다.

## 메시지코드관리 (레거시 화면 + 기능 추가 요청)

- 목록(IDX · 등록일 · 프로그램서비스 · 메세지코드 · 사용언어 · 메세지 타이틀 · 메세지 내용 · 시스템 메시지 · 상태) | 오른쪽 상세(수정 · 삭제).
- 개별 등록: 「등록」 → 프로그램서비스 · 사용언어 · 메세지코드 · 메세지 타이틀 · 메세지 내용 · 시스템 메시지 → 「메세지코드정보저장」. 같은 프로그램 · 언어 · 코드 중복은 막음.
- 일괄 등록: 「메세지코드업로드」 → 엑셀(.xlsx · .csv) 선택 → 미리보기(등록 가능 · 새 코드 · 내용 바뀜 · 오류 줄) → 「자료등록」. 같은 코드는 내용을 갱신, 오류 줄은 제외. 양식 내려받기 제공. (.xlsx 읽기는 SheetJS를 CDN에서 불러옴 — 안 되면 CSV로 안내)
- 초기화: 「메세지코드초기화」 → 확인창 → 「예」 시 전체 삭제(감사LOG · 데이터수정LOG), 「아니요」 시 그대로. SysAdmin · 연구소 개발자만 보임.

## LOG관리 › 인증요청 LOG (레거시 「인증요청로그」, 이전 이름 API 요청 LOG)

- 목록(IDX · 등록일 · 제휴사ID · 제휴사명 · cmd · API 커맨드 · 승인번호 · 요청일시, 최근 순) | 오른쪽 상세(요청 정보 + API LOG 요청 원문 JSON, 읽기 전용 · 복사). 기본 기능은 검색.
- 원문의 비밀번호 · 토큰은 가려서 저장(••••). 다른 LOG 메뉴는 기존 목록 화면 그대로.

## 발급관리 › 카드번호발급관리 (레거시 「카드발급 관리」)

- 목록(전산코드 · 발급날짜 · 카드종류 · 카드번호(가림) · 카드잔액 · 회원타입 · 회원아이디 · 회원명 · 관련거래번호 · 카드발급타입 · 상태) | 오른쪽 상세(기본정보 · 자료관리 탭).
- 발급: 국가코드 · 발급날짜 · 발급고객구분 · 카드발급자(찾기) · 카드종류 · 카드번호(「자동발급」은 가상카드번호채번관리의 대기 번호를 가져오고, 저장하면 채번 쪽 상태도 발급) · 카드비밀번호 → 「카드발급등록저장」. 이미 발급된 번호는 막음.
- 사용중지(카드중지이유 필수 · 변동사유) · 카드거래현황(충전 · 사용 내역, 마지막 잔액 = 카드잔액) · 메모등록(자료관리 탭).

## 발급관리 › 계좌번호발급관리 (레거시 「계좌번호 발급 관리」)

- 목록(전산코드 · 발급날짜 · 거래은행 · 계좌번호 · 계좌잔액 · 최소/최대이체금액 · 이체수수료 · 거래제한 · 회원타입 · 회원아이디 · 회원명 · 상태) | 오른쪽 상세(기본정보: 계좌 정보 · 이체 한도 · 수수료 · 발급 고객 · 관리 정보 / 자료관리: 메모).
- 발급: 계좌발급자(찾기) · 거래은행 · 계좌번호(「자동발급」= 가상계좌번호채번관리의 대기 번호, 저장 시 채번 쪽도 발급) · 예금주 · 계좌비밀번호 · 계좌거래제한구분 · 최소/최대 이체금액 · 이체수수료 · 은행이체 → 「계좌발급등록저장」.
- 사용중지(계좌중지이유 필수) · 계좌거래현황(입금 · 이체출금 · 수수료, 마지막 잔액 = 계좌잔액) · 한도 · 수수료 수정(최대 ≥ 최소, 데이터수정LOG) · 메모등록.

## 고객센터 › 상담관리 (레거시 「상담 관리」, 이전 메뉴 이름 댓글관리)

- 목록(전산코드 · 등록날짜 · 상담회원아이디 · 상담회원명 · 상담자아이디 · 상담자명 · 상담종류 · 상담제목 · 처리 · 상태) | 오른쪽 상세(댓글정보: 상담 정보 + 상담내용 · 처리결과 / 기타정보: 상태 · 변동날짜 · 변동사유 · 자료등록자).
- 등록(회원상담내용등록: 등록날짜 · 회원구분 · 상담회원(찾기) · 상담종류 · 상담제목 · 상담내용 | 처리내용) · 처리결과등록(회원상담처리내용등록 — 저장하면 상담자 = 처리한 관리자, 처리완료) · 삭제(선택한 건, 논리삭제).
- 상담원(CS) 역할은 처리결과등록 가능, 삭제는 불가.
